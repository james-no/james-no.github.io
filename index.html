About me

I'm James No, a senior in the Bachelor of Science in Computer Science program at Skagit Valley College, graduating in June 2027. My main interests are backend and full-stack software engineering, with a growing focus on application security.

I came to software engineering through a less typical path. After earning a psychology degree from Washington State University, I helped run my family's restaurants, then served four years in the U.S. Army as a Geospatial Intelligence Imagery Analyst. I was promoted to Sergeant in just over two years, trained junior analysts, and wrote standard operating procedures that made our team's work more consistent. Those roles taught me to stay calm under deadlines, document what I do, and communicate clearly across teams.

Today I bring that same discipline to code. I've led QA and production deployment for a team-built Spring Boot and React application, built an AI interview coach with Python and Azure OpenAI, and contributed a merged test to an open-source energy dashboard.

Career goal: to start as a new-grad software engineer in 2027, ideally on a team that builds secure, reliable backend systems, and to keep growing toward security-focused engineering.

Task Mentor: Full-Stack Mentoring Marketplace

Team project · CS 301 · Fall 2025
  • Java 21
  • Spring Boot 3
  • Spring Security
  • React 18
  • PostgreSQL
  • JWT
  • Render
  • Netlify

Problem / purpose

Students need an easy way to find mentors and book time with them. Our four-person team built a web marketplace where students search mentors by multiple filters and book sessions, with separate permissions for students and mentors.

My role and contributions

  • Led QA: designed and ran tests across 15+ features, including JWT login, role-based access control, booking workflows, and multi-filter mentor search.
  • Owned production deployment: Spring Boot backend on Render and React frontend on Netlify, configuring environment variables, CORS policies, and JWT secrets.
  • Merged the final release pull requests, including a Maven wrapper permissions fix that unblocked the build, the production release, and the final README.
  • Wrote the technical documentation: architecture overview, REST API contracts, local setup guide, and a QA report covering functional and edge-case tests.

Outcome and lessons learned

We shipped a fully deployed, working application. The biggest lesson was that "works on my machine" is not done: hosting the frontend and backend separately meant CORS rules and environment variables had to be exactly right, and secrets like the JWT key had to stay out of the code. Testing role-based access also showed me how easily permission bugs hide unless you test as every type of user.

Interview Practice Bot: AI Interview Coach

Solo project
  • Python
  • Azure OpenAI (GPT-4.1)
  • Multi-turn conversation

Problem / purpose

Practicing for technical and behavioral interviews is hard without someone to ask questions and give honest feedback. I built a conversational coach that runs realistic, role-specific mock interviews and scores the answers.

My role and contributions

  • Designed a five-phase interview flow: setup, question generation, per-answer evaluation, targeted feedback, and a scored session summary.
  • Managed the full conversation history so the coach keeps context across an entire session and can judge how answers improve over time.
  • Built an evaluation pipeline that rates each answer on completeness, clarity, technical accuracy, and communication, then produces a ranked list of improvements.

Outcome and lessons learned

The result is a tool I use for my own interview prep. Breaking the interview into clear phases made the AI's behavior far more predictable than a single open-ended prompt. I also learned to treat model output as something to check, not trust blindly, which matters when AI is part of an engineering workflow.
